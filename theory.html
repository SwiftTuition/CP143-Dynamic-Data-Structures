Dynamic Data Structures

Master linked lists, stacks, queues, and binary trees - the foundation of efficient algorithms and real-world applications.

Estimated Time: 10-12 hours

Good day, good people.

Up until now, every data structure you've used has had a fixed size. Arrays must be declared with a specific size, and that size cannot change during program execution. But what if you're building a music playlist app and don't know how many songs the user will add? What if you're creating a task manager where users can add and remove tasks at any time?

This is where dynamic data structures come in. They can grow and shrink during program execution, adapting to your needs. Think of static arrays as a parking lot with numbered spaces - once it's full, you're out of luck. Dynamic data structures are like a train - you can add or remove cars as needed.

In this learning module, you'll master four essential dynamic data structures that form the backbone of countless real-world applications.

1. Introduction to Dynamic Data Structures

Static vs Dynamic: What's the Difference?

Let's compare static and dynamic data structures:

Static Data Structures:

  • Size is fixed at compile time
  • Memory requirements never change during execution
  • Examples: Arrays, structures (without pointers)
  • Fast access by index
  • Can waste memory if you allocate too much
  • Can run out of space if you allocate too little

Dynamic Data Structures:

  • Size can change during program execution
  • Memory is allocated and deallocated as needed
  • Examples: Linked lists, stacks, queues, trees
  • Efficient memory usage
  • Can grow as large as available memory allows
  • Require careful memory management

The Four Fundamental Dynamic Structures

1. Linked Lists

A linear collection of elements where you can insert and delete anywhere. Think of it as a chain where you can add or remove links at any point.

2. Stacks

Last-In, First-Out (LIFO) structure. Like a stack of plates - you can only add or remove from the top. Used by compilers and operating systems for function calls.

3. Queues

First-In, First-Out (FIFO) structure. Like a queue at a bank - people join at the back and are served from the front. Used for print spoolers and network packet routing.

4. Binary Trees

A hierarchical, non-linear structure. Each element can have two children. Used for efficient searching and sorting - a tree with 1,000,000 elements requires only about 20 comparisons to find any value.

Real-World Applications

  • Web browsers: Use stacks for back/forward navigation history
  • Music players: Use queues for playlists
  • Operating systems: Use stacks for function call management
  • Databases: Use trees for fast data retrieval
  • GPS navigation: Uses trees for finding optimal routes
  • Social networks: Use linked lists and trees to manage connections
Key Insight

All dynamic data structures rely heavily on pointers and structures. If you're comfortable with pointers, you'll find these structures natural and intuitive.

2. Self-Referential Structures

A self-referential structure is a structure that contains a pointer to another structure of the same type. This is the foundation of all dynamic data structures.

The Basic Node Concept

Here's a simple self-referential structure:

struct listNode {
    char data;
    struct listNode *nextPtr;
};
typedef struct listNode ListNode;
typedef ListNode *ListNodePtr;

Let's break this down:

  • char data - stores the actual value
  • struct listNode *nextPtr - a pointer to another listNode
  • The nextPtr acts as a "link" connecting one node to the next
  • Setting nextPtr to NULL indicates there's no next node (end of the structure)
┌─────────────────┐ │ ListNode │ ├──────┬──────────┤ │ data │ nextPtr │ │ 'A' │ ●─────┼───> (points to next node) └──────┴──────────┘

Using typedef for Cleaner Code

The typedef statements let us write cleaner code:

// Without typedef:
struct listNode *ptr1;

// With typedef:
ListNodePtr ptr1;  // Much cleaner!

3. Dynamic Memory Management

Static structures are allocated at compile time. Dynamic structures need runtime memory allocation and deallocation. This is where malloc(), free(), and sizeof() come in.

The malloc() Function

The malloc() function allocates memory at runtime:

void *malloc(size_t size);
  • Takes the number of bytes to allocate as an argument
  • Returns a void pointer to the allocated memory
  • Returns NULL if memory allocation fails

Example usage:

ListNode *newPtr = malloc(sizeof(ListNode));

if (newPtr != NULL) {
    newPtr->data = 'C';
    newPtr->nextPtr = NULL;
} else {
    printf("Memory allocation failed!\n");
}

The sizeof() Operator

The sizeof() operator returns the number of bytes needed for a type:

sizeof(char)      // Typically 1 byte
sizeof(int)       // Typically 4 bytes
sizeof(ListNode)  // Size of entire structure

Always use sizeof() with malloc() - don't hardcode sizes, as they vary across systems.

The free() Function

The free() function returns memory to the system:

void free(void *ptr);

Every malloc() must have a corresponding free(), or you create a memory leak.

ListNode *tempPtr = malloc(sizeof(ListNode));
// ... use tempPtr ...
free(tempPtr);
tempPtr = NULL;  // Good practice: prevent dangling pointer
Memory Layout: Before malloc(): HEAP: [ Available Memory ................................................ ] After malloc(sizeof(ListNode)): HEAP: [ Used Block ] [ Available Memory ................................ ] ^ | newPtr points here After free(newPtr): HEAP: [ Available Memory ................................................ ]

Memory Leaks

A memory leak occurs when you allocate memory but never free it:

// BAD: Memory leak!
for (int i = 0; i < 1000; i++) {
    ListNode *ptr = malloc(sizeof(ListNode));
    // ... use ptr ...
    // Forgot to free!
}
// You just leaked 1000 nodes worth of memory
// GOOD: Proper cleanup
for (int i = 0; i < 1000; i++) {
    ListNode *ptr = malloc(sizeof(ListNode));
    // ... use ptr ...
    free(ptr);
}

Dangling Pointers

A dangling pointer points to memory that has been freed:

// BAD: Dangling pointer!
ListNode *ptr = malloc(sizeof(ListNode));
free(ptr);
ptr->data = 5;  // CRASH! ptr points to freed memory

// GOOD: Set to NULL after freeing
ListNode *ptr = malloc(sizeof(ListNode));
free(ptr);
ptr = NULL;  // Now we can't accidentally use it
⚠️ Critical: Secure C Programming

MEM01-C/MEM30-C: Always initialize pointers to NULL or a valid address.

MEM01-C: Set pointers to NULL immediately after calling free() to prevent double-free vulnerabilities.

ERR33-C: Always check that malloc() did not return NULL before using the pointer.

4. Linked Lists

A linked list is a linear collection of self-referential structures called nodes, connected by pointer links. Unlike arrays, linked lists can grow and shrink dynamically, and you can insert or delete nodes anywhere in the list.

How Linked Lists Work

Each node contains:

  • Data (can be any type)
  • A pointer to the next node

The list is accessed via a pointer to the first node (often called the "head"). To access subsequent nodes, you follow the nextPtr from one node to the next.

Linked List Structure: startPtr | v ┌──────┬─────┐ ┌──────┬─────┐ ┌──────┬─────┐ ┌──────┬──────┐ │ data │next │───>│ data │next │───>│ data │next │───>│ data │ NULL │ │ 'A' │ ● │ │ 'B' │ ● │ │ 'C' │ ● │ │ 'D' │ │ └──────┴─────┘ └──────┴─────┘ └──────┴─────┘ └──────┴──────┘

Searching a Linked List

To search for a value, start at the head and follow the links:

// Search for value = 'C'
char value = 'C';
ListNodePtr currentPtr = startPtr;

while (currentPtr != NULL && value != currentPtr->data) {
    currentPtr = currentPtr->nextPtr;
}

if (currentPtr != NULL) {
    printf("Found: %c\n", currentPtr->data);
} else {
    printf("Not found\n");
}

Inserting into a Linked List

To insert a new node with value 'C' between 'B' and 'D':

  1. Create a new node with malloc()
  2. Set the new node's data
  3. Link previous node to new node
  4. Link new node to next node
// Assume previousPtr points to 'B' and currentPtr points to 'D'
ListNodePtr newPtr = malloc(sizeof(ListNode));
newPtr->data = 'C';
newPtr->nextPtr = NULL;

previousPtr->nextPtr = newPtr;  // 'B' -> 'C'
newPtr->nextPtr = currentPtr;   // 'C' -> 'D'
Insertion Process: Before: prev current | | v v ┌───┬──┐ ┌───┬──┐ │ B │●─┼──────>│ D │ │ └───┴──┘ └───┴──┘ Step 1: Create new node new | v ┌───┬──┐ │ C │ │ └───┴──┘ Step 2: Link previous to new prev current | | v v ┌───┬──┐ ┌───┬──┐ │ B │●─┼───┐ │ D │ │ └───┴──┘ │ └───┴──┘ v ┌───┬──┐ │ C │ │ └───┴──┘ Step 3: Link new to current prev current | | v v ┌───┬──┐ ┌───┬──┐ │ B │●─┼───┐ │ D │ │ └───┴──┘ │ └───┴──┘ v ┌───┬──┐ │ C │●─┼───> └───┴──┘

Deleting from a Linked List

To delete a node:

  1. Save a pointer to the node to delete
  2. Link the previous node to the next node (bypass the deleted node)
  3. Free the deleted node
// Delete the node pointed to by currentPtr
ListNodePtr tempPtr = currentPtr;
previousPtr->nextPtr = currentPtr->nextPtr;
free(tempPtr);

Linked Lists vs Arrays

Feature Arrays Linked Lists
Size Fixed at compile time Dynamic, grows/shrinks at runtime

⚠️ Critical Warning

The linked list is "lost" if you incorrectly modify the head pointer. Always use a temporary pointer for traversal, never modify the head directly unless you're adding/removing from the beginning.

5. Stacks

A stack is a constrained version of a linked list where elements can only be inserted or deleted from one end, called the top. This makes a stack a Last-In, First-Out (LIFO) structure.

Stack Concept

Think of a stack of plates in a cafeteria. You can only add a plate to the top (push), and you can only remove a plate from the top (pop). You cannot access plates in the middle without first removing all the plates on top.

Stack Structure: topPtr | v ┌───┬──┐ │ 2 │●─┼──> NULL (Top of stack - most recently added) └───┴──┘ ^ | ┌───┬──┐ │ 4 │●─┘ └───┴──┘ ^ | ┌───┬──┐ │ 9 │●─┘ └───┴──┘ ^ | ┌───┬──┐ │ 1 │●─┘ (Bottom of stack - oldest element) └───┴──┘

Stack Operations

Push (Insert at Top):

void push(StackNodePtr *topPtr, int value) {
    StackNodePtr newPtr = malloc(sizeof(StackNode));

    if (newPtr != NULL) {
        newPtr->data = value;
        newPtr->nextPtr = *topPtr;  // New node points to old top
        *topPtr = newPtr;            // Top now points to new node
    } else {
        printf("%d not inserted. No memory available.\n", value);
    }
}

Pop (Remove from Top):

int pop(StackNodePtr *topPtr) {
    StackNodePtr tempPtr = *topPtr;
    int popValue = (*topPtr)->data;

    *topPtr = (*topPtr)->nextPtr;  // Move top to next node
    free(tempPtr);                  // Free the old top

    return popValue;
}

Stack Applications

  • Function Calls: When you call a function, the return address is pushed onto a stack. When the function returns, the address is popped.
  • Automatic Variables: Local variables are stored on the stack and automatically cleaned up when the function returns.
  • Expression Evaluation: Compilers use stacks to evaluate mathematical expressions and convert them to machine code.
  • Undo/Redo: Text editors use stacks to implement undo (each action is pushed) and redo functionality.
  • Browser History: The back button uses a stack to remember previous pages.

6. Queues

A queue is another constrained version of a linked list where elements are inserted at one end (the tail/back) and removed from the other end (the head/front). This makes a queue a First-In, First-Out (FIFO) structure.

Queue Concept

Think of a queue at the bank or a grocery checkout line. People join at the back of the line and are served from the front. The first person in line is the first person served - that's FIFO.

Queue Structure: headPtr tailPtr | | v v ┌───┬──┐ ┌───┬──┐ ┌───┬──┐ ┌───┬──────┐ │ 2 │●─┼───>│ 4 │●─┼───>│ 9 │●─┼───>│ 1 │ NULL │ └───┴──┘ └───┴──┘ └───┴──┘ └───┴──────┘ (front) (back) Remove Insert here here

Queue Operations

Enqueue (Insert at Tail):

void enqueue(QueueNodePtr *headPtr, QueueNodePtr *tailPtr, char value) {
    QueueNodePtr newPtr = malloc(sizeof(QueueNode));

    if (newPtr != NULL) {
        newPtr->data = value;
        newPtr->nextPtr = NULL;

        if (isEmpty(*headPtr)) {
            *headPtr = newPtr;  // Queue was empty
        } else {
            (*tailPtr)->nextPtr = newPtr;  // Link old tail to new node
        }
        *tailPtr = newPtr;  // Update tail pointer
    }
}

Dequeue (Remove from Head):

char dequeue(QueueNodePtr *headPtr, QueueNodePtr *tailPtr) {
    char value = (*headPtr)->data;
    QueueNodePtr tempPtr = *headPtr;

    *headPtr = (*headPtr)->nextPtr;  // Move head to next node

    if (*headPtr == NULL) {
        *tailPtr = NULL;  // Queue is now empty
    }

    free(tempPtr);
    return value;
}

Queue Applications

  • Print Spooling: Documents sent to a printer are queued. First document sent is first to print.
  • CPU Scheduling: Processes waiting for CPU time are placed in a queue.
  • Network Packets: Data packets waiting to be transmitted are queued.
  • Breadth-First Search: Graph algorithms use queues to explore nodes level by level.
  • Customer Service: Call center systems use queues to manage waiting customers.

7. Binary Trees

All the structures we've seen so far are linear - you can only move forward through them. Binary trees are nonlinear, two-dimensional structures. Each node can have up to two children, creating a hierarchical structure.

Tree Terminology

Binary Tree Example: 5 <-- Root node / \ / \ 2 7 / \ / \ 1 4 6 9 / \ 3 8 Terminology: - Root node: 5 (first node, no parent) - Left child of 5: 2 - Right child of 5: 7 - Parent of 2: 5 - Left subtree of 5: all nodes under 2 (1, 2, 4, 3) - Right subtree of 5: all nodes under 7 (6, 7, 9, 8) - Leaf nodes: 1, 3, 6, 8 (no children)
  • Root node: The first node (5 in the example)
  • Parent: A node that has children below it
  • Child: A node connected below a parent (left child, right child)
  • Siblings: Nodes with the same parent
  • Leaf node: A node with no children
  • Subtree: A child node and all its descendants

Binary Search Tree (BST)

A binary search tree has a special property that makes searching very efficient:

  • All values in the left subtree are less than the parent node
  • All values in the right subtree are greater than the parent node

This property holds for every node in the tree, not just the root.

Tree Node Structure

struct treeNode {
    struct treeNode *leftPtr;
    int data;
    struct treeNode *rightPtr;
};
typedef struct treeNode TreeNode;
typedef TreeNode *TreeNodePtr;

Inserting into a Binary Search Tree

New nodes are always inserted as leaf nodes. The recursive algorithm:

  1. If tree is empty, create the root node
  2. If value < current node's data, go left
  3. If value > current node's data, go right
  4. Repeat until you find an empty spot
void insertNode(TreeNodePtr *treePtr, int value) {
    if (*treePtr == NULL) {
        // Found empty spot - create new node
        *treePtr = malloc(sizeof(TreeNode));

        if (*treePtr != NULL) {
            (*treePtr)->data = value;
            (*treePtr)->leftPtr = NULL;
            (*treePtr)->rightPtr = NULL;
        }
    } else {
        if (value < (*treePtr)->data) {
            insertNode(&((*treePtr)->leftPtr), value);  // Go left
        } else if (value > (*treePtr)->data) {
            insertNode(&((*treePtr)->rightPtr), value); // Go right
        }
        // If value == data, it's a duplicate - ignore it
    }
}

Tree Traversals

Traversing a tree means visiting every node. There are three common orders:

1. Inorder Traversal (Left - Root - Right):

void inOrder(TreeNodePtr treePtr) {
    if (treePtr != NULL) {
        inOrder(treePtr->leftPtr);     // Visit left subtree
        printf("%3d", treePtr->data);  // Process node
        inOrder(treePtr->rightPtr);    // Visit right subtree
    }
}

For a BST, inorder traversal prints values in ascending order: 1, 2, 3, 4, 5, 6, 7, 8, 9

2. Preorder Traversal (Root - Left - Right):

void preOrder(TreeNodePtr treePtr) {
    if (treePtr != NULL) {
        printf("%3d", treePtr->data);  // Process node
        preOrder(treePtr->leftPtr);    // Visit left subtree
        preOrder(treePtr->rightPtr);   // Visit right subtree
    }
}

Output: 5, 2, 1, 4, 3, 7, 6, 9, 8

3. Postorder Traversal (Left - Right - Root):

void postOrder(TreeNodePtr treePtr) {
    if (treePtr != NULL) {
        postOrder(treePtr->leftPtr);   // Visit left subtree
        postOrder(treePtr->rightPtr);  // Visit right subtree
        printf("%3d", treePtr->data);  // Process node
    }
}

Output: 1, 3, 4, 2, 6, 8, 9, 7, 5

Why Trees Are Efficient

A balanced binary search tree with n elements has a maximum of log₂(n) levels:

  • 1,000 elements: ~10 comparisons maximum
  • 1,000,000 elements: ~20 comparisons maximum

Compare this to a linked list where you might need to check all n elements to find a value. Trees are incredibly efficient for searching and sorting.

8. When to Use Which Structure

Structure Selection Guide

Use This When You Need Examples
Array Direct access by index, fixed size known in advance Student grades (fixed class size), game board
Linked List Dynamic size, frequent insertions/deletions anywhere Music playlist, task list, contacts
Stack LIFO behavior, tracking history Undo/redo, function calls, expression evaluation

Memory Management Best Practices

  1. Always check malloc() return value 
    ptr = malloc(sizeof(Node));
if (ptr == NULL) {
    printf("Memory allocation failed!\n");
    return;
}
  2. Free every malloc() 
    // Every malloc needs a matching free
Node *ptr = malloc(sizeof(Node));
// ... use ptr ...
free(ptr);
ptr = NULL;  // Prevent dangling pointer
  3. Set pointers to NULL after freeing

    This prevents accidental use of freed memory and double-free vulnerabilities.

  4. Use helper functions to free entire structures 
    void freeList(NodePtr startPtr) {
    while (startPtr != NULL) {
        NodePtr tempPtr = startPtr;
        startPtr = startPtr->nextPtr;
        free(tempPtr);
    }
}

Common Errors to Avoid

⚠️ Common Mistakes
  • Losing the head pointer: Always use a temporary pointer for traversal
  • Forgetting to set nextPtr to NULL: Causes undefined behavior when traversing
  • Not checking for NULL before dereferencing: Causes segmentation faults
  • Memory leaks: Forgetting to free allocated memory
  • Dangling pointers: Using freed memory
  • Double free: Freeing the same memory twice

Performance Considerations

Operation Array Linked List BST
Access by index O(1) O(n) N/A
Search for value O(n) O(n) O(log n)
Insert at beginning O(n) O(1) O(log n)
Delete from middle O(n) O(n) O(log n)

Note: O(n) means proportional to n, O(log n) means logarithmic, O(1) means constant time

Summary

You've mastered the four fundamental dynamic data structures:

  • Self-referential structures contain pointers to their own type, enabling linking
  • malloc() and free() manage dynamic memory allocation and deallocation
  • Linked lists provide dynamic, flexible linear storage with easy insertion/deletion
  • Stacks enforce LIFO ordering - critical for function calls and undo operations
  • Queues enforce FIFO ordering - essential for waiting lines and scheduling
  • Binary trees provide hierarchical storage with incredibly fast searching

These structures form the foundation of advanced algorithms and real-world applications. Master them, and you'll be able to solve complex problems efficiently.
