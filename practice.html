Memory Management Best Practices

Golden Rules

  • Always check malloc(): if (ptr == NULL) { /* handle error */ }
  • Free what you allocate: Every malloc() needs a free()
  • Set to NULL after freeing: free(ptr); ptr = NULL;
  • Don't use after freeing: Accessing freed memory is undefined behavior
  • Free in reverse order: Free child nodes before parent nodes

Compilation & Debugging Commands

  • Basic compile: gcc -Wall -Wextra -g program.c -o program
  • With sanitizers: gcc -g -fsanitize=address program.c -o program
  • Check memory leaks: valgrind --leak-check=full ./program
  • GDB debugging: gdb ./program

Common Memory Errors to Avoid

  • Memory leak: Forgetting to free allocated memory
  • Dangling pointer: Using a pointer after freeing it
  • Double free: Calling free() twice on same pointer
  • Invalid access: Accessing memory outside allocated bounds
  • Lost reference: Losing the head pointer before freeing list

Tips for Success

Before You Code

  • Draw the data structure on paper first
  • Trace through operations manually with a small example
  • Identify edge cases: empty structure, single element, etc.
  • Plan your memory allocation and deallocation strategy

While Coding

  • Start with helper functions (createNode, isEmpty, etc.)
  • Test each function individually before combining
  • Use printf debugging to trace pointer values
  • Check for NULL pointers before dereferencing
  • Add comments explaining complex pointer manipulations

Testing Strategy

  • Unit test: Test each function with simple inputs
  • Edge cases: Empty structure, single element, full structure
  • Stress test: Large data sets (1000+ elements)
  • Memory test: Run valgrind on all test cases
  • Visual verification: Print structure after each operation

Debugging Pointer Issues

  • Print pointer addresses to track where they point: printf("%p\n", (void*)ptr)
  • Use assert() to verify assumptions: assert(head != NULL)
  • Draw diagrams showing pointer connections before and after operations
  • Use GDB to step through code and inspect pointer values

Time Complexity Comparison

Linked List Operations

  • Insert at beginning: O(1)
  • Insert at end: O(n) without tail pointer, O(1) with tail
  • Delete: O(n) - must search first
  • Search: O(n)
  • Access by index: O(n)

Stack Operations

  • Push: O(1)
  • Pop: O(1)
  • Peek: O(1)
  • All operations are constant time!

Queue Operations

  • Enqueue: O(1) with tail pointer
  • Dequeue: O(1)
  • Front: O(1)
  • All operations are constant time with proper implementation!

Binary Search Tree Operations (Average Case)

  • Insert: O(log n)
  • Search: O(log n)
  • Delete: O(log n)
  • Traversal: O(n) - must visit all nodes
  • Note: Worst case (unbalanced tree) is O(n) for insert/search/delete
